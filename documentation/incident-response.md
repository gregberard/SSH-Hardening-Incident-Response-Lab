Incident Response Report
Incident Overview

A simulated unauthorized SSH login attempt was performed against an Ubuntu Server to practice a basic blue-team incident response workflow.

The objective was to identify an exposed service, simulate suspicious activity, investigate security logs, apply a defensive change, and validate the improvement.

Lab Environment

Target System:

Ubuntu Server
OpenSSH service
Port 22

Attacker System:

Kali Linux

Network Environment:

VirtualBox Host-Only Network
Detection

Suspicious SSH authentication activity was generated by attempting to access the Ubuntu Server using an invalid user account.

The simulated attack used:

ssh fakeuser@192.168.56.103

The authentication attempts failed and generated security events on the server.

Investigation

SSH authentication logs were reviewed to determine:

The username used during the attempt
The source IP address
The authentication result
The time of the events

The logs confirmed that failed SSH authentication attempts were detected and recorded by the system.

Findings

The investigation confirmed:

SSH was an active service on the server.
Remote authentication was enabled.
Failed login attempts were logged.
Authentication controls could be improved.
Response

The SSH service configuration was reviewed and hardened.

The maximum number of failed authentication attempts was reduced to limit repeated login attempts.

The remediation details are documented in the remediation report.

Conclusion

This lab demonstrated a complete incident response workflow:

Identify
Investigate
Respond
Validate

The exercise provided hands-on experience with Linux administration, SSH security, authentication monitoring, and defensive security practices.
